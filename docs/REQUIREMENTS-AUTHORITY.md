# PIRA Requirements Authority

1. Latest product-owner instructions and agreed conversation decisions are primary.
2. Earlier agreed decisions apply unless explicitly superseded.
3. Uploaded academic archives, source code, WBS, and presentations are historical references and candidates for reuse, not binding architecture.
4. Changes require rationale, security impact, and tests documented in the implementation log.

## Confirmed direction
- Responsive personal and business workspaces with explicit switching.
- Session mode choice in Settings, with server-enforced expiration and authorization.
- Inventory, indexing, reminders, search, categories, reorder, and reporting.
- Basic, Access, Business entitlements and separately privileged administrator/developer functions.
- Verified accounts, MFA, audit logging, least privilege.
- PIRA Copilot Ask, Action, and Insight, with explicit confirmation for state-changing actions.
- Prefer a lightweight .NET 8 API with HTML/CSS/JavaScript where practical; review compatibility and support lifecycle before deployment.

## Legacy items not automatically adopted
- Client-only tier access codes and demo credentials.
- Public developer registration and seeded administrators.
- Academic timeline, prototype payment screens, old pricing, and placeholder workflows.
- Old API secrets, provider bindings, and permissive CORS.

Unresolved choices must remain marked as decisions, not invented implementation facts.
